# Security Policy

## Supported version

Security fixes are applied to the latest release on the default branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting feature on the repository **Security** tab and include:

- affected component and version;
- reproduction steps or a minimal proof of concept;
- expected and observed impact;
- suggested mitigation, when available.

Do not include production credentials, personal data, or customer transactions. Maintainers will acknowledge a complete report, investigate it privately, coordinate a fix, and publish an advisory when appropriate.

## Scope

Relevant areas include authentication, authorization/RLS, tenant isolation, payment and webhook integrity, wallet encryption, secrets, data exposure, dependency vulnerabilities, and release integrity.
